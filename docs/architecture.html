TerrainSim architecture

Clean Architecture layout from plan.md section 8. Outer layers on top, core rules at the bottom.

Per use case

Each of GenerateTerrain, DropBall, Step, SaveScene, LoadScene gets its own Controller, Presenter, InputData, OutputData, two boundaries, an Interactor and a small DataAccessInterface.

Simulation loop

The Swing Timer in SimulationPanel calls StepController.execute(dt) about 60× a second. Balls move through the same layers as every other action.

Shared scene

InMemorySceneDataAccess implements each use case's narrow interface so DropBall, Step and SaveScene all see the same Scene.

Swappable details

Replace the LLM provider, JSON files or the physics engine by adding a new class in the outer ring. Interactors don't change.
